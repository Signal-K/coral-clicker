name: Creative task scoping preferences
description: What kinds of creative/design work the user enjoys vs. avoids — applies to all task scoping
type: feedback
---

User enjoys tasks that are **spatial / structural / system design**:
- Layout design (launchpad, star map, location maps, structure positions)
- Designing mission orders, outputs, outcomes (structured system with defined elements)
- Grid/component design (rocket builder grid, species reference grids)
- Deciding what goes where when the elements are already known

User does NOT enjoy:
- Long-form script or prose writing
- Doing the same type of thing repetitively (e.g. write a 150-word profile × 8 species)
- Starting from scratch with no direction on what elements belong ("draw the HUD" without knowing what goes in it)

**Why:** Stated directly when reviewing creative tickets on 2026-04-02.

**How to apply:**
- Convert prose-writing tasks into structured grid/table fill-in tasks when possible
- Never scope a design task without specifying the confirmed elements first — tell them what's already decided before asking them to design the container
- Merge repeated-writing tasks into one structured reference doc exercise
- Spatial/layout tasks (maps, panels, grids) are high-enjoyment — prioritise these and scope them well
