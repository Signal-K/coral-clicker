# Coral MVP Audit

_Date: 2026-04-11_

## Scope

This audit covers the current Coral game state, the archived-but-incomplete Knowns tasks, the Godot source/UI structure, and the latest local tour artifacts in `artifacts/tour/`.

## Executive Verdict

Coral is a playable prototype with a recognizable loop, but it is not yet MVP-ready.

The strongest parts are:

- The core loop exists: route map -> identify phase -> reef puzzle -> result/win flow.
- The tutorial and identify phase are materially better than placeholder quality.
- The project already has containerized test paths and a tour harness.

The main blockers are:

- The shipping web/PWA shell is still a developer host UI, not a player-facing product shell.
- The 10-level content exists structurally, but the data is not yet wired to real subject identifiers.
- Several UX-critical panels are still prototype-grade or underdesigned.
- Offline/reward sync is implemented in principle but not proven to MVP confidence.

## Locked Product Decisions

- The Tank is in MVP.
- Initial Tank MVP scope:
  - Bonus fish and coral earned in levels are stored in The Tank.
  - The Tank is a decorative sandbox space where the player can interact with stored species.
  - The Tank passively produces resources.
- Identify is mandatory on every non-tutorial level.
- Web/PWA is the primary MVP shipping platform for all users while native distribution is unavailable.

## Containerized PWA Check

The instruction was to skip the installed-PWA simulation if setup would require more than 500 MB of installation.

That threshold is exceeded here:

- Local Docker already contains `coral-tour:latest` at about 894 MB.
- The Dockerfiles depend on Debian/Node/Godot images and would require a heavyweight setup on a fresh machine.

Result:

- I did not do a fresh installed-PWA container setup.
- I used the existing tour artifacts and source review instead.

## Current Product Read

### What is already working well

- The home/route screen has a readable progression structure and obvious current-level focus.
- The identify phase is now a dedicated full-screen experience, which matches the product direction much better than a popup.
- The gameplay scene communicates the objective, fish cards, turn action, and reef state in a way that is learnable.
- The result modal and win modal confirm that the loop is mechanically complete.

### Where the current build still feels unfinished

- The web host is still branded as `Coral Host Controls` and exposes direct bridge/debug controls rather than a production shell. See [web/app/page.tsx](/Users/scroobz/Navigation/Coral/web/app/page.tsx:55).
- The Tank hub is functional but reads as a utilitarian management screen rather than a retention surface. See [project/scenes/hub/the_tank.gd](/Users/scroobz/Navigation/Coral/project/scenes/hub/the_tank.gd:44).
- The turn results panel uses a simple sorted list with only three status labels and no special treatment for stressors or dense species mixes. See [project/scenes/ui/turn_results_panel.gd](/Users/scroobz/Navigation/Coral/project/scenes/ui/turn_results_panel.gd:21).
- The identify phase still exposes a non-tutorial skip path even though identify is now locked as mandatory on every non-tutorial level. See [project/scenes/ui/identify_phase.gd](/Users/scroobz/Navigation/Coral/project/scenes/ui/identify_phase.gd:27).
- The map layout is responsive, but it still represents the earlier route version rather than the intended location-spine v2 design. See [project/home_screen.gd](/Users/scroobz/Navigation/Coral/project/home_screen.gd:160).

## MVP Requirements

These are the minimum items that should be complete before calling Coral an MVP.

### Must ship

1. A player-facing web/PWA shell.
2. A stable tutorial, identify phase, and 10-level progression path.
3. Real subject mapping for levels, not placeholder or empty `subject_id` coverage.
4. A readable reef HUD and results flow at both low and high species counts.
5. A Tank experience that stores bonus species, supports decorative interaction, and passively produces resources.
6. A verified offline/reconnect path for classifications and pending rewards.
7. Basic audio pass for the core loop.
8. One reliable QA tour or acceptance flow that can be rerun before release.

### Can be simplified or de-scoped

- The Tank can remain lightweight, but it cannot be removed from MVP.
- Field-guide/discovery copy can be cut from MVP.
- Advanced trait/breeding customization can stay deferred.
- Deep world-map v2 polish can be staged if the current map is cleaned up enough.

## Concrete MVP Blockers Found

### Product shell blocker

The current browser entry point is a debug/control wrapper, not a user product shell. It includes direct level buttons, Supabase read/write controls, and bridge logs. See [web/app/page.tsx](/Users/scroobz/Navigation/Coral/web/app/page.tsx:57).

### Content/data blocker

The active level data currently has no visible `subject_id` fields in the level definitions reviewed here, even though the backlog explicitly says real subject IDs must be assigned. See [project/data/starter_levels.json](/Users/scroobz/Navigation/Coral/project/data/starter_levels.json:6) and [active.md](/Users/scroobz/Navigation/Coral/.knowns/backlog/active.md:26).

### Results readability blocker

The results panel currently treats all rows the same and does not distinguish target species from threat species, which will break down in later levels. See [project/scenes/ui/turn_results_panel.gd](/Users/scroobz/Navigation/Coral/project/scenes/ui/turn_results_panel.gd:67).

### Hub quality blocker

The Tank is now confirmed as part of MVP, but the current implementation does not yet clearly communicate stored bonus species, decorative interaction, or passive production as a polished player feature. See [project/scenes/hub/the_tank.gd](/Users/scroobz/Navigation/Coral/project/scenes/hub/the_tank.gd:108).

### Mandatory identify blocker

Non-tutorial identify is now a locked requirement, but the current identify scene still has a skip affordance outside tutorial flow. See [project/scenes/ui/identify_phase.gd](/Users/scroobz/Navigation/Coral/project/scenes/ui/identify_phase.gd:32).

## UX Notes

### Home / route map

- Strongest current screen visually.
- The left rail explains the goal clearly.
- The route still feels more like a static board than a living reef journey.

### Identify phase

- Strong improvement over a dialog-based flow.
- Clear two-column structure.
- Needs its non-tutorial skip path removed or redesigned so the mandatory identify rule is actually enforced.

### Gameplay screen

- Loop is understandable.
- Fish cards and action buttons are readable.
- Dense information is beginning to compete for space.
- Environmental state presentation is functional but underdesigned.

### Turn result / win states

- Win modal communicates reward logic well enough.
- Turn result panel is the weakest core-loop surface for late-game readability.

### Tank

- Explains itself, but lacks delight, strong visual hierarchy, and a clear representation of stored bonus species as part of the MVP reward loop.

## Components That Need New Design Work

- Turn results panel for 3-species vs 6-8-species reefs.
- Water conditions HUD widget.
- Bleaching event entry state and persistent in-level indicator.
- World map/location spine v2.
- Tank hero/status/payout presentation and stored-species sandbox treatment.
- Fail screen polish and specific fail-reason treatment.
- PWA/web wrapper shell so the browser build feels like the game, not internal tooling.

## Recommended Sprint Shape

### Sprint goal

Make Coral feel like a coherent MVP instead of a promising prototype.

### Highest-priority sequence

1. Replace the debug web shell with a product shell.
2. Finish level content wiring, including real `subject_id` assignments.
3. Enforce mandatory identify on all non-tutorial levels.
4. Redesign the results panel, water HUD, and Tank MVP surfaces.
5. Verify offline/pending reward behavior.
6. Add core audio and run the QA tour pass.
